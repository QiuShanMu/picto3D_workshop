# 软件需求

对齐日期：2026-08-26。  
业务源：[零售多SKU图生3D全流程方案.md](../零售多SKU图生3D全流程方案.md)。  
接口源：[腾讯混元生 3D API 概览](https://cloud.tencent.com/document/product/1804/120838)。

本文写「软件要做什么」。拍摄工位怎么搭、灯怎么打，仍以作业规范为准，不在本仓库实现。

## 1. 目标

在固定拍摄规范下，把一批 SKU 的多角度商品图送进混元，拉回 GLB/OBJ，自动过几何/尺寸关卡，人工抽检查，失败按策略重跑，合格品按目录归档。日吞吐受混元默认 3 路并发约束，不追求买并发包。

实现上**先分模块闭环，不先做一步到位 E2E**。每个单元能单独喂夹具、单独出 `report.json`；整批队列与重跑放到各单元都跑通之后。详见 [spec-architecture.md](./spec-architecture.md) 第 6 节。验收仍按「单 SKU 能从入队走到归档」衡量，但是用单元组合出来的，不是第一天就写死一条大流水线。

## 2. 角色与系统边界

| 角色 | 人做 | 软件做 |
|---|---|---|
| 拍摄组 | 场景、拍摄、补拍 | 只校验入队图片是否齐、命名是否对 |
| 数据处理组 | 异常决策 | 去背景、压 API 图、上传、下载、归档落盘 |
| 3D 生成 | 选档位（专业版参数） | 调混元、排队、轮询、记 JobId |
| 质量组 | 360° 人工判定 | 自动校验报告、检查队列、质量汇总 |
| 项目负责人 | 降级/放弃 | 看批次看板（v1 本地文件即可） |

## 3. 范围内（v1）

1. SKU 清单导入（CSV/JSON）：编号、名称、品类、材质、尺寸 mm、颜色、批次、特殊说明。
2. 接收 `SKU编号_<index>.jpg`（或 png）。**除 `01` 外均可缺省**；有几张收几张。不要因为不是 10 张就拒收。
3. 预处理：去背景（可关）、校验张数/分辨率/格式、另存一份给混元用的压缩图。
4. 本地生成队列：同时在跑的混元任务默认最多 3 个。
5. 混元专业版 3.1：正面 + 最多 7 个命名多视图；PBR 默认开；产出以实际 `ResultFile3Ds` 为准（预期 GLB + OBJ）。
6. JobId 有效期内轮询；`DONE` 后 24 小时内把文件落到本地版本目录。
7. 自动校验：文件能开、体积合理、流形/破面、bbox 与实物尺寸比例。
8. 人工检查页：用浏览器转 GLB；记录合格 / 微调后重跑 / 不合格。
9. 重跑计数与版本保留（`current` + `v1/v2/…`），次数上限见作业规范。
10. 归档目录：`品类/批次号/SKU编号/`，含终稿模型、原图、校验报告、检查记录。

## 4. 范围外（v1 明确不做）

| 作业规范里有 | 处理 |
|---|---|
| 场景搭建、灯光、转台硬件 | 不软件化 |
| 飞书多维表格看板 | v1 用本地 `batch.json` / CSV；飞书后做 |
| 按品类的混元「预设模板」（鞋服/家居/电子） | 混元 API 无此参数；v1 一套默认档，参数可手工改 |
| 外观自动评分 ≥80（满分 100） | 无现成可靠库；v1 不做外观打分，低几何分或边界件进人工检查 |
| 纹理「无明显拉伸/接缝」的自动视觉判定 | v1 只查贴图分辨率是否 ≥1024；观感留给人 |
| FBX 必出 | v1 只收默认 GLB+OBJ；要 FBX 再调 `Convert3DFormat` 或 `ResultFormat` |
| 自托管 Hunyuan3D / TRELLIS | 不做 |
| 摄影测量备胎（Meshroom/COLMAP） | 不做 |
| 混元人物/绑骨/动作/组件 | 不做 |
| 购买混元并发叠加包 | 不纳入方案 |

## 5. 与作业规范对齐后的解释

这些不是推翻规范，是接到混元 API 后必须改的实现细节。

| 规范原文 | 对齐后的软件行为 |
|---|---|
| 10 张/SKU（8 周视 + 俯 + 仰） | 原图 10 张全归档；送给混元最多 8 张（见混元 spec 视角表）；135°、225° 不上传 |
| 分辨率建议 ≥2048 | 入队原图按此检查；**API 图**压到长边 1280–1600，保证多视合计 ≤8MB |
| 20–50 SKU 同时提交 | 批次可以 20–50；**同时 RUN 的任务 ≤3**，其余在本地排队 |
| 生成 5–15 min/SKU | 作为超时告警参考，不是 SLA；超时继续轮询直到 FAIL/DONE 或 JobId 过期 |
| 输出 GLB + OBJ/FBX | 默认收 GLB+OBJ；FBX 非 v1 必选项 |
| 重跑 ≤3（按问题类型还有 2/1） | 状态机按规范分类型计数；「需重拍」只出工单，软件不自动重拍 |
| 云盘备份 30 天 | v1 先本地归档；COS 备份与混元入图可以共用一个桶，开工时再配 |

## 6. 验收（首个可运行版本）

用 1 个真实或夹具 SKU（10 张规范图 + 尺寸）证明：

1. 能入队、能提交混元、能把 `JobId` 写进清单。
2. `DONE` 后本地出现模型文件，且 24 小时后不再依赖云端 URL。
3. 自动校验产出一份机器可读报告（几何 / 尺寸 / 文件）。
4. 人工检查能打开 GLB 并写下判定。
5. 模拟一次生成失败：自动重提，版本目录多一档，计数 +1。
6. 合格 SKU 能归档到三级目录，清单状态为「已归档」。

未开通混元账号时，允许用 mock 适配器跑通 3–6；接真 API 后再补 1–2。

## 7. 非功能

- 密钥不入库：`TENCENTCLOUD_SECRET_ID` / `TENCENTCLOUD_SECRET_KEY`（或等价配置），只读环境变量。
- 混元失败（含风控）不扣积分，必须把 `ErrorCode` / `ErrorMessage` 留下。
- 单 SKU 处理可中断恢复：只存 JobId 不够，文件必须落盘。
- 日志按批次可检索，能回答「这个 SKU 第几次、用了哪些视角、花了多少积分」。
