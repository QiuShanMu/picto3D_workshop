# 混元图生 3D 网格实验

对齐日期：2026-08-26。  
目的：在铺开拍摄工位和跑批之前，用**同一组图、不同视角缺省**摸清混元 3.1 真正吃哪几张。  
机读格子：[experiments/hunyuan-view-grid.v1.json](../experiments/hunyuan-view-grid.v1.json)。

不是产线。每格是一次独立 Submit，结果落在 `data/experiments/<run_id>/<cell_id>/`。

## 1. 为什么先做实验

工位是人手转到台面标识，张数天然不齐。若没测过就按 8 张开发，后面发现「3 张和 6 张没差」会白拍；若发现「缺背面必歪」又要改操作提示。

实验只动**上送哪些图**和少量官方开关。不扫 FaceCount、极速版、文生。

## 2. 固定条件（除格子外不要变）

| 项 | 值 |
|---|---|
| 接口 | 专业版 `SubmitHunyuanTo3DProJob` |
| 第一阶段 Model | `3.1` |
| 第一阶段 PBR | `true` |
| 图 | **同一 SKU、同一套预处理结果**，格子只是子集 |
| 正面 | 永远来自 `*_01` → `ImageUrl` |
| 并发 | 1（实验期不要占满 3 路） |
| 评分 | 自动校验 + 人看 1–5 分（几何 / 纹理 / 是否缺面） |

第一阶段用 1 个好拍的硬壳 SKU（几何清楚、少透明少高光）。材质对比放到第三阶段。

## 3. 缺省规则（和产线一致）

- 没有 `01`：格子标 `expect=reject`，本地直接拒，不打混元（省积分）。
- 其它 index 可缺；04/06 有也不上送。
- 某格需要的 index 在测试集里没有：该格 `skip`，在记录里写原因，不补拍凑数（除非整组图重拍）。

## 4. 第一阶段：视角网格（主实验）

同一套图、3.1、PBR 开。一格 ≈ 单图 30 积分或带多视 40 积分。

| cell | 上送 index | 混元含义 | 要验证的问题 |
|---|---|---|---|
| V1 | 01 | 只正面 | 单图基线，手转最少能不能不转 |
| V2 | 01+05 | 正+背 | 缺侧面是否还能围起来 |
| V3 | 01+03 | 正+左 | 不对称缺省会不会歪 |
| V4 | 01+03+05 | 正+左+背（开源 2mv 经典） | 3 张是否就够 |
| V5 | 01+03+05+07 | 四向 | 加右面值不值 |
| V6 | 01+02+03+05+07+08 | 四向+两枚 45° | 手转 45° 标识有没有用 |
| V7 | 01+02+08 | 正+两枚斜 45° | 只打斜视、不打正侧 |
| V8 | 01（故意不传 MultiView） | 同 V1，防回归 | 对照 |

V6 是「手转一圈、去掉混元没有的 135/225」后的满配。V3 是「标识没对准、只随手多拍一张侧」的真实缺省。

**不要**第一阶段就上 09/10：单机位本来就没有。有翻面图再加 V9=`V5+09`、V10=`V5+10`。

预估：8 格成功提交约 **240–320 积分**（约 25–35 元预付）。开通赠送 100 分不够跑完整表，要先有积分包或后付费。

## 5. 第二阶段：只在优胜格上加开关

先看 V1 / V4 / V5 / V6 的人评分，留 **2 个优胜格**，再叉乘（每项单独加，不要全因子）：

| 因子 | 格子 | 目的 |
|---|---|---|
| PBR 关 | 优胜格 ×1 | 10 积分是否买得值 |
| Model=3.0 | 仅 V4、V5（3.0 没有 45°/顶底） | 3.1 是否值得绑死 |
| 去背景 vs 不去 | 优胜格 ×1，同一分辨率 | D435i 白底还要不要 rembg |

大约再 4–6 次，**160–240 积分**。

## 6. 第三阶段：材质冒烟

用第二阶段的 **1 个配方**，再跑 2 个 SKU：一块织物或鞋、一件反光/深色。只看会不会系统性垮，不重新扫视角。约 **80 积分**。

## 7. 记录与判定

每格目录：

```
data/experiments/<run_id>/<cell_id>/
  request.json      # 实际提交的视角列表（脱敏，无密钥）
  query.json        # Status、积分、Error
  model.glb / obj   # 有则留下
  validate.json     # 现有 validate 报告
  review.json       # 人打的三个 1–5 分 + 一句话
```

汇总表字段：`cell_id, views, status, credits, seconds, geo, tex, complete, notes`。

怎么收结论（写回工位提示，不是写死代码分支）：

| 现象 | 工位默认动作 |
|---|---|
| V4 ≥ V6，且差 ≤0.5 分 | 台面只留 0°/90°/180°（+ 可选 270°），少转 45° |
| V6 明显好于 V4 | 保留 45° 标识，提示转满 6 个上送档 |
| V1 就够用 | 实验 SKU 可能太简单，第三阶段必须再测难材质后再减档 |
| V3 明显歪 | 提示「至少再拍对面或另一侧」 |
| V2 背面仍缺 | 180° 标识必须拍 |

## 8. 和开发的衔接

- **现在不写混元客户端**也没关系：格子已在 JSON 里，密钥到了做「按 cell 子集提交」即可。
- preprocess 继续允许缺文件；实验跑手可以先手动组 `api/` 子集。
- 工位软件的默认提示文案，等本实验汇总后再填，不要先写死「必须 8 张」。
