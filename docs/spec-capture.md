# 拍摄到入库 Spec（D435i 定机位 + 手转）

对齐日期：2026-08-26。  
上游作业：[零售多SKU图生3D全流程方案.md](../零售多SKU图生3D全流程方案.md)。  
下游已有：[preprocess](./spec-architecture.md)、[混元视角表](./spec-hunyuan-api.md)、`pipeline/views.py`。  
生产化篇（双人协同/防漏拍/批次装配/降级）：[spec-production-capture.md](./spec-production-capture.md)。

本文只定拍摄工位与入库数据包。不在这里写混元调用。开发仍按「单模块闭环」。

## 1. 混元入参是不是决定数据结构？

**决定交接层，不决定采集层。**

| 层 | 谁说了算 | 里面有什么 |
|---|---|---|
| 采集包 `capture/` | 工位物理：台面角度标识、手转、D435i 双流 | RGB + 深度 + 内参 + 每帧 yaw/pose + 清晰度 |
| 入站包 `incoming/` | 已实现的预处理契约 | `SKU_01.jpg`…`SKU_10.jpg` |
| 上送包 `api/` | 混元 3.1 槽位 + 8MB | 最多 8 张压缩图；04/06 不上送 |

混元只认：一张正面 `ImageUrl`，外加命名视角 `left/right/back/top/bottom/left_front/right_front`。它不认深度、IMU、转台角度、10 张均分。

所以：**采集要按工位把能记的都记全；交给流水线时再投影成 01–10。** 不要在按下快门的那一刻就把包压成「只剩 8 个混元 URL」，否则深度和 135°/225° 归档图会丢掉，后面校验尺度、重拍也对不齐。

已有映射表（人面对相机，商品逆时针转到下一档，序号增大向左）继续用。采集软件只填 `index` + `yaw_deg` + `pose`，不要另造一套视角名。

**缺省是一等公民。** 除 `01` 正面外，任一档可以不拍、拍坏跳过。会话可以只有 1 张或 3 张就入库。网格实验会先测「缺哪些图混元仍能用」，再决定工位默认要拍几档。

## 2. 工位假设（v1）

- **一台 D435i，机位锁死**，镜头对着操作台中心。
- **物体转、相机不转。** 不设电动转台；台面做 0°/45°/… 标识，人手转到挡位后软件确认拍摄。
- 灯光、白底仍按作业规范；软件不管布光硬件。
- 不要做转台驱动、步进协议。提示「请转到 45° 标识」+ 空格确认即可。

### 2.1 D435i 能力与缺口

| 项 | D435i | 作业规范 / 混元 | 处理 |
|---|---|---|---|
| RGB | 最高约 1920×1080，定焦 | 规范建议 ≥2048；混元 128–5000 | **本工位以 1080p 为准**；预处理 `min_edge` 对本工位降到 1080，不要用 2048 卡死入库 |
| 深度 | 约 1280×720，室内 0.3–3m | 混元不用 | 写入采集包，留给尺度估计 / 以后；不进混元 |
| IMU | 有 | 混元不用 | 开拍记一条，用于发现相机被碰 |
| 工作距 | 0.5–0.8m 可用 | 规范 50–80cm | 对齐；定焦必须先对好距离再锁脚架 |
| 俯 / 仰 | 单机位水平看，**拍不到真俯视/真底面** | 规范 09/10；混元 3.1 可选 | 见 2.2，v1 不假装能拍到 |

1080p 对混元合法。质量上限在相机，不在软件。若以后要海报级纹理，再加一台高分辨率 RGB，采集包加 `camera=rgb_dslr`，交接格式不变。

### 2.2 俯仰怎么处理（单机位的硬限制）

一台锁死的 D435i **不能**在不翻面、不改机位的情况下拍到规范里的真俯视和真仰视。

| 方案 | 动作 | 效率 | v1 |
|---|---|---|---|
| P0 斜视锁死 | 相机略俯（约 20–35°），只跑 yaw 8 张 | 最快，约 3–5 分钟/SKU | **主路径** |
| P1 二次机位 | 8 张后把相机改到顶视，只拍 `09` | 多一次校准 | 可选 |
| P2 翻面 | 商品翻底，再拍一张当 `10` | 慢、姿态会变 | 可选；透明件/平底件再开 |

v1 闭环：**8 张 yaw 就能入库并进入预处理。** `09`/`10` 缺省不阻断。混元缺非正面槽位本来就允许。不要为了凑满 10 张把翻面做成默认动作。

斜视的 8 张仍然按 01–08 映射到混元（含 left_front 等）。混元没有「斜视」字段，这是工位妥协。

### 2.3 色彩校正（白平衡 + 平场）

D435i 在暖色 5500K 工位下有**两层**色偏，来源不同、需分开处理：

| 层 | 表现 | 根因 | 处理 |
|---|---|---|---|
| 整体色温 | 全画面偏黄/偏蓝 | 自动白平衡漂移 | 关闭自动 WB/AE，冻结白平衡到 5500K |
| 空间色偏 | 中心圆内偏青、边缘偏品红 | 镜头光学阴影 / 传感器响应不均 | **平场校正（shading LUT）** |

平场校正做法（`pipeline/capture/shading.py`）：

1. 移开商品，让画面被**均匀中性面**（白/灰）填满，抓 8 帧平均作参考帧。
2. 分块（默认 16×16）估计每块 R/G、B/G 通道比，以中心区为中性锚点，反推出逐像素增益 LUT。
3. 保存为 `data/captures/shadings/<serial>_shading.json`；采集时对每帧逐像素应用，消除中心/边缘色偏。
4. 换机、换布光色温需重新标定；单帧/空白帧不用重标。

标定命令：`python -m pipeline.capture --calibrate-shading --wb 5500`（采集时无需再标定，自动按串号加载 LUT）。

## 3. 拍摄动作（人 + 软件）

每个 SKU 一次会话：

1. **扫/键入 `sku_id`**：采集台支持两种 SKU 前置录入——
   - **图像识别**：开拍前拍一张 SKU 条码图（Code128/Code39/EAN/UPC/QR 混合都可以），`pyzbar` 识别后**自动填入 SKU**；识别失败可人工键入核对。条码图落盘 `color/barcode.jpg` + `barcode.json`，**不进 `frames`、不入图生3D输入**。
   - **手持扫码枪 Qp2100（键盘仿真 Keyboard Wedge）**：USB 直连即插即用，扫入字符以快速击键打进**当前焦点输入框**（结尾回车）。采集台页面内用前端 `keydown` **捕获阶段**监听，按「相邻字符间隔 <60ms 判为同一梭、回车/Tab 终结」聚合，自动填 SKU 并锁定；捕获后强制聚焦 SKU 框、实时回填字符，锁后再扫**忽略**（防后续扫码误入其它框）。**不要用后台全局钩子（pynput / 串口 / msvcrt 控制台读键）**——扫码枪是键盘模式，字符进前台焦点窗口，后台钩子抓不到；RDP 远程键鼠也会占用输入通道。
   键入 `batch_id`。
2. 商品摆正，**定义正面 = 0° = 01**（商标/主视觉朝相机）。
3. 预览：曝光、主体占比约 60–70%、白底干净。
4. 拍 `01`，软件写盘并做清晰度门闩；糊了当场重拍，不进下一档。
5. 人把商品转到下一档台面标识，拍 `02`…；中途可跳过、可结束（缺省）。
   - **拍摄中随时回看已拍图**：采集台「已拍图片」缩略图网格实时列出已拍各档，点击放大进 lightbox（左右翻 / Esc 关闭），核对角度与构图；点「回采集·重拍这档」即把该档设回当前档直接补拍，拍摄与检查同页完成，无需返回文件目录。
6. 可选：顶视 / 翻面。
7. 会话结束：写出 `capture.json`（`frames` 只含实际拍到的档，条码字段在顶层 `barcode`），状态 `captured`。
8. 交接：导出到 `data/incoming/<batch>/<sku>/`，缺的 index 不生成文件，状态 `handed_off`。

> SKU 条码是**前置录入环节**（SO1b/S1b）：先拍条码 → 识别 → 锁定 SKU → 才开始视角采集。若识别出的值与人工键入不一致，以人工为准，条码值仅存档+提示核对。

一批多个 SKU 只换商品、不拆相机。P0 若拍满 8 档，目标仍约 3–5 分钟/SKU。

## 4. 数据包（采集层）

```
data/captures/<batch_id>/<sku_id>/
  capture.json
  color/01_yaw000.jpg
  color/02_yaw045.jpg
  ...
  color/08_yaw315.jpg
  color/barcode.jpg            # SKU 条码图（开拍前采集，不入 frames、不入图生3D）
  barcode.json                 # 条码识别结果
  depth/01_yaw000.png          # 16-bit，可选但默认开
  depth/02_yaw045.png
  ...
  camera.json                  # 内参、串号、分辨率，会话级一份即可
```

`barcode.json` 形状：

```json
{
  "value": "APP-0812-001",
  "raw": "APP-0812-001",
  "type": "CODE128",
  "source": "pyzbar",
  "image": "color/barcode.jpg",
  "captured_at": "2026-08-26T08:00:00+08:00",
  "manual": false
}
```

`capture.json` 形状（字段保持少，和混元槽位对齐的只有 `index` / `hunyuan`；`barcode` 为**可选**顶层字段，缺省兼容旧数据）：

```json
{
  "schema": "capture.v1",
  "sku_id": "APP-0812-001",
  "batch_id": "0812",
  "station_id": "d435i-desk-1",
  "operator": "",
  "started_at": "2026-08-26T08:00:00+08:00",
  "pose_mode": "yaw_manual_marks",
  "rotation": { "method": "manual_marks", "step_deg": 45, "direction": "ccw" },
  "camera": {
    "model": "d435i",
    "serial": "",
    "color": "1920x1080",
    "tilt_deg": 25,
    "color_controls": {
      "white_balance": 5500,
      "exposure": 156,
      "gain": 64,
      "auto_white_balance": false,
      "auto_exposure": false
    },
    "shading_lut": "shadings/<serial>_shading.json"
  },
  "barcode": {
    "value": "APP-0812-001",
    "image": "color/barcode.jpg",
    "captured_at": "2026-08-26T08:00:00+08:00",
    "auto": true
  },
  "frames": [
    {
      "index": "01",
      "yaw_deg": 0,
      "pose": "yaw",
      "hunyuan": "ImageUrl",
      "color": "color/01_yaw000.jpg",
      "depth": "depth/01_yaw000.png",
      "ok": true
    }
  ],
  "status": "captured"
}
```

规则：

- `index` 必须是 `pipeline/views.py` 的 `01`–`10`，禁止 `front`/`left` 当文件名。
- `hunyuan` 从视图表抄，`04`/`06` 为 `null`。
- `pose`：`yaw` | `top` | `bottom`。P0 只有 `yaw`。
- 深度失败不挡入库；`depth` 可空，RGB 门闩过了就能交接。
- `frames` 缺档合法；没有的 index 不要写占位空文件。
- 文件先写 `.tmp` 再改名，避免半截图被交接扫到。
- `barcode` 是**可选**顶层字段：`barcode.jpg` / `barcode.json` 只存档，**永不写进 `frames`**，因此 `handoff → incoming → preprocess → 混元` 全程无感。

## 5. 交接层（衔接到现有 preprocess）

采集软件**不调用**混元，只做一次投影：

```
captures/<batch>/<sku>/color/01_yaw000.jpg
        → incoming/<batch>/<sku>/<sku>_01.jpg
```

缺哪些 index 就不生成哪些文件。preprocess / 混元：**只要有 `01` 就可往下走**；04/06 有也只归档、不上送。

交接清单（SKU 级，可附在 `incoming/.../handoff.json` 或只靠目录）：

- `sku_id` / `batch_id` / `source=capture.v1`
- 已导出的 index 列表
- 原图长边（D435i 一般为 1920）
- 指向 `captures/.../capture.json` 的相对路径（重拍、查深度用）

这样跑批上传仍吃现在的 `incoming/`，不用为混元再发明第三套命名。

## 6. 工具盘点（要开发 vs 复用）

按闭环拆，不要做成「拍摄+上传+混元」一条龙。

| 序号 | 工具 | 闭环 | 复用 | v1 |
|---|---|---|---|---|
| T1 | 工位采集 | 预览 → 按档位拍 → `capture/` + `capture.json` | Intel RealSense SDK 2 / `pyrealsense2` | **要做** |
| T2 | 转档提示 | 屏幕显示下一档角度 + 台面标识，空格确认 | 不接电机 | **做在 T1 里** |
| T3 | 当场门闩 | 清晰度 / 过曝占比 / 文件写全 | OpenCV 或 numpy；不要上检测大模型 | **要做**（规则要少） |
| T3b | 平场校正 | 白平衡冻结 + 中心/边缘色偏校正 | `shading.py`，独占一个闭环可先跑 | **要做**（标定一次，采集自动应用） |
| T4 | 交接导出 | `capture/` → `incoming/` 命名 | 直接用 `pipeline/views.py` | **要做** |
| S1 | 采集页面 | 预览 + 点击一下采集一张 | Flask + pyrealsense2 | **可选（快速抽查帧用）** |
| S1b | SKU 条码采集 | 拍条码 → 识别 → 自动填 SKU → 锁定后拍视角；或 Qp2100 扫码枪键盘仿真直接打进 SKU 框 | `pyzbar` + OpenCV 兜底（图像）；前端 keydown 捕获聚合（扫码枪） | **要做**（识别失败/无库/无枪时人工键入兜底） |
| T5 | 预处理 | 已有 `python -m pipeline.preprocess` | 本仓库 | 已有；对本工位放宽 `min_edge` |
| T6 | 混元落盘 / 校验 / 检查 | 已规划的后段 | 本仓库 | 不在本方案开工 |

不做（本阶段）：转台电机、机械臂、双机位同步、用深度做摄影测量、把深度送给混元、自动布光。

T1+T2+T3 做成**一个**工位程序。T4 单独 CLI。混元支持情况用 [网格实验](./spec-hunyuan-grid.md) 先测，再决定工位默认拍几档。

## 7. 建议开发顺序

1. **网格实验设计**（本文档的姊妹篇）：密钥到了先跑视角缺省，再冻工位默认动作。
2. **T4 交接**（无相机）：夹具 + 缺档 `capture.json` → `incoming/` → preprocess。
3. **T1+T3**：接 D435i，按标识手转，允许中途结束。
4. 工位 `min_edge=1080`。
5. 实验结论出来后，再把「默认拍哪几档」写进工位提示，而不是先写死 8 张。

## 8. 验收（采集闭环，不含混元）

1. 一个 SKU 可只拍 3 档或拍满 8 档；`capture.json` 只列实拍帧，`index`/`yaw_deg`/`hunyuan` 与视图表一致。
2. 糊图被拒、当场重拍，目录里不会留失败档当正式帧。
3. T4 导出后，preprocess 能跑通，且 `api/` 里没有 `_04`/`_06`。
4. 拔掉深度流仍能完成 1–3。
5. 换 SKU 不拆相机，会话只换 `sku_id` 目录。
6. 标定平场后，均匀中性面上中心区与边缘区的 R/G、B/G 通道比收敛（spread 明显小于未校正），中心圆与边缘无明显色偏。
